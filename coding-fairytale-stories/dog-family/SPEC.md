  그림·이야기는 그 글자를 읽고 싶게 만드는 장치다.

## 2. 한 줄 줄거리
비가 와서 그네를 못 타게 된 강아지 자매 보리와 두두가, 아빠 코코가 꺼내 온 네모로
배를 짓고 온 가족이 바다와 우주를 지나 돌아와, 무지개 아래에서 노래하고 잠든다.

## 3. 이 책의 설계 원칙 (제일 중요한 대목)

예전 판은 **그림이 주인공이고 글자는 자막**이었다. 실제로 재보니:

| | 예전(장면 16개) | 지금(페이지 42개) |
|---|---|---|
| 글자 크기 | 27px 고정 | **76px** (태블릿) · 37px (폰) |
| 한 화면 글자 수 | 29자 (3줄 문단) | **6.6자** 평균, 최대 8자 한 줄 |
| 글자가 차지하는 면적 | 화면의 12.5% | 30% 안팎 |
| 글자 하나를 만질 수 있나 | 불가 (문단이 통짜 텍스트) | **글자 하나 = 버튼 하나** |
| 읽어 줄 때 어디를 읽는지 | 표시 없음 | **그 글자가 켜짐** |
| 넘김 | 자동 (기계가 정함) | **아이 손** |
| 핵심 글자 반복 | 우연에 맡김 (80종 중 24%가 1번) | **핵심 20자를 정해 각 3번 이상** |

원칙 여섯 가지:
1. **한 페이지에 한 줄, 여덟 자를 넘지 않는다.** 넘으면 큰 글자에서 두 줄로 접힌다.
   `check_batchim.js` 가 8자 초과를 오류로 잡는다.
2. **글자 하나가 곧 버튼이다.** 받침이 없으니 **한 글자 = 한 소리**로 정확히 떨어진다.
   이 규칙의 진짜 값어치가 여기 있다.
3. **읽어 줄 때 글자가 차례로 켜진다.** 소리와 모양이 붙는 순간을 만든다.
4. **읽어 주는 도중이라도 아이가 글자를 누르면 읽기를 멈추고 그 글자를 들려준다.**
   아이 손이 기계보다 먼저다.
5. **저절로 넘어가지 않는다.** 앞·뒤 버튼은 크고 늘 같은 자리에 있다.
6. **핵심 글자를 먼저 정하고 이야기를 맞춘다.** 쓰고 나서 세는 게 아니다.

## 4. 핵심 글자 (CORE 20자)
`보 리 두 코 모 나 무 그 네 비 배 바 다 고 래 사 과 우 주 노`
— 이름(보리·두두·코코·모모)과 사물(나무·그네·비·배·바다·고래·사과·우주·노래) 위주.
각 글자가 본문에 **최소 3번** 나오도록 문장을 맞췄다. 검사 스크립트가 횟수를 센다.

- **브라우저로 열어 보고서야 잡은 것들**
  - **글자 위치의 기준이 통째로 틀려 있었다.** `#stage` 에 등장 애니메이션(`transform`)을
    걸었더니 **높이 0인 #stage 가 위치 기준(containing block)이 되어** `top:56%` 가
    전부 0으로 계산됐다. 등장인물 전원이 그림 맨 위에 붙어 있었다.
    → `#stage { position:absolute; inset:0 }` 로 그림칸을 채우게 해서 해결.
  - **강아지가 공중에 떠 있었다(75명).** 예전 전체화면(720px) 기준 y값을 그림칸(542px)에
    그대로 썼다. 배경(800×600)이 slice 로 들어갈 때의 배율(1.28)·오프셋(-113)을 계산해
    지면선을 구하고, 원근 순서는 지키면서 58~70% 안으로 일괄 이동.
  - **바나나·둥지 소품도 떠 있었다.** 소품 높이 비율로 바닥 좌표를 계산해 내림.
  - **긴 줄이 두 줄로 접혔다.** "우와! 배가 다 되어요"(8자)처럼 문장부호까지 더하면
    넘친다 → 6자로 줄이고, 검사 스크립트에 8자 상한을 넣어 다시 안 생기게 했다.
  - **읽어 주는 중에 글자를 눌러도 반응이 없었다.** `reading` 이면 무시하도록 짰는데,
    아이는 읽는 도중에 누른다 → 읽기를 멈추고 그 글자를 들려주도록 바꿈.
  - **폰 세로에서 글줄이 접히고 글자가 34px까지 줄었다.** 좁은 화면 전용 규칙(자간·여백
    축소)으로 한 줄 유지. 이때 `.pic` 의 `flex` 를 건드렸다가 **그림칸이 8px로 찌그러졌다**
    — 안이 전부 절대배치라 콘텐츠 높이가 0이기 때문. flex 는 그대로 두고 타이포만 조정.

### 다음에 참고할 점
- **"글자를 노출한다"는 말은 크기·개수·반복 셋을 다 정해야 한다.** 예전 판은 글자를
  넣긴 했지만 27px 자막에 29자씩, 반복 없이 흩뿌렸다. 노출은 됐어도 학습은 안 됐다.
  **어휘 목록(CORE)을 먼저 정하고 이야기를 맞추는** 순서가 맞다.
- **받침 없이 쓸 때 제일 잘 먹힌 우회는 넷.**
  ① 다른 말로(마당→나무 아래, 벽돌→네모, 거실→여기, 집→자리)
  ② 조사 생략("바나나 주세요")
  ③ 현재형·청유형("~해요", "~가자")
  ④ **감정을 낱말 대신 그림으로**("시무룩" → "두두 귀가 처져요") ← 제일 좋았다.
  꾸미는 말(큰·커다란·예쁜·따뜻한)은 거의 다 받침이라 **문장을 쪼개 서술어로** 옮긴다.
- **엔진을 그대로 쓰면 그 엔진이 정한 것만 만들 수 있다.** 자막 크기·자동 넘김·
  미니게임 껍데기가 전부 engine.js 에 박혀 있어 story.js 로는 바꿀 수 없었다.
  남의 엔진에서는 **그림만 빌리고 보여 주는 방식은 직접 짜는** 편이 낫다.
- **CSS `transform` 은 절대배치의 기준을 바꾼다.** 애니메이션 하나 붙였다가 화면 전체
  배치가 무너졌고, 스크린샷을 보기 전에는 알 수 없었다. **검사 스크립트는 글자는 잡아도
  배치는 못 잡는다 — 눈으로 볼 것.**

  ABC / 덧셈 3+2·2+2·4+1 / 뺄셈 5-2 / 단어 친구·로봇·보물·**바나나** / build 3·4·5.
